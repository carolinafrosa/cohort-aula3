# Story 1.31 — Memória Persistente de Buscas por Usuário

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.31
**Prioridade:** Média
**Estimativa:** G (6–10h)

---

## Descrição

Cada conversa começa do zero. O bot não sabe que o mesmo número de WhatsApp já consultou projetos antes, e não consegue referencias consultas anteriores (*"Como você perguntou antes sobre Joinville..."*). Isso elimina qualquer sensação de relacionamento contínuo.

Esta story implementa uma camada de memória persistente por número de telefone usando **Supabase** (já disponível como opção no `.env.example`), armazenando as últimas 5 consultas realizadas por cada usuário. O `ProcessaMensagem` passa a consultar esse histórico e pode enriquecer o contexto antes de classificar a intenção.

**Valor:** Memória é o que diferencia um assistente de um menu de autoatendimento. Mesmo sem personalização, o simples reconhecimento de buscas anteriores transforma a experiência. ROI 1.3 (esforço alto, mas valor também alto).

---

## Workflow de Desenvolvimento

```
1. Criar tabela no Supabase:
   CREATE TABLE user_history (
     id SERIAL PRIMARY KEY,
     phone_number TEXT NOT NULL,
     query_text TEXT,
     intent TEXT,
     result_count INT,
     created_at TIMESTAMPTZ DEFAULT NOW()
   );
   CREATE INDEX ON user_history(phone_number, created_at DESC);

2. Importar docs/flow/projeta-sc.json no n8n
3. Criar nó "ConsultaHistorico" (HTTP Request → Supabase REST API):
   - Input: número de telefone do usuário
   - Output: últimas 5 consultas (query_text + intent)
   - Executar ANTES de ProcessaMensagem

4. Modificar ProcessaMensagem para receber e usar o histórico no contexto
5. Criar nó "SalvaHistorico" (HTTP Request → Supabase REST API):
   - Input: phone, query_text, intent, result_count
   - Executar APÓS ConsultaProjetos, junto com o envio da resposta

6. Testar: fazer 3 buscas com mesmo número → verificar histórico no Supabase
7. Testar: historico é recuperado na 4a conversa
8. Exportar e substituir docs/flow/projeta-sc.json
9. Commitar
```

## Acceptance Criteria

### AC-1: Tabela de histórico criada no Supabase
- [ ] Tabela `user_history` criada com campos: `phone_number`, `query_text`, `intent`, `result_count`, `created_at`
- [ ] Índice em `(phone_number, created_at DESC)` para recuperação eficiente

### AC-2: Histórico consultado antes de processar
- [ ] O nó `ConsultaHistorico` recupera as últimas 5 consultas do número de telefone atual
- [ ] O histórico é disponibilizado no contexto de `ProcessaMensagem`

### AC-3: Histórico salvo após cada consulta bem-sucedida
- [ ] O nó `SalvaHistorico` registra: número de telefone, texto da query, intenção classificada e quantidade de resultados retornados
- [ ] Somente consultas que chegaram ao Oracle são salvas (não salvar erros ou menus)

### AC-4: Histórico usado no contexto (versão básica)
- [ ] Quando o usuário faz uma consulta ambígua e tem histórico, `ProcessaMensagem` inclui o município ou categoria da última busca como contexto para o LLM
- [ ] Exemplo: usuário buscou "Joinville" antes e digita "projetos de rodovia" → contexto inclui "usuário costuma buscar em Joinville"

### AC-5: Privacidade e retenção
- [ ] Histórico armazena apenas query_text e intent — nunca dados pessoais além do número (que é o identificador mínimo necessário)
- [ ] Registros com mais de 30 dias não são retornados (filtro por `created_at`)

## Dependências

- Credenciais Supabase configuradas no `.env` e acessíveis pelo n8n (`SUPABASE_URL`, `SUPABASE_ANON_KEY`)
- Story 1.28 (confidence score) — o contexto histórico pode ajudar a resolver intenções com baixa confiança

---

## Riscos

- **Supabase sem configuração:** Se as credenciais não estiverem disponíveis no n8n, o nó `ConsultaHistorico` deve falhar silenciosamente (graceful degradation) — o fluxo principal não pode ser bloqueado por ausência de histórico
- **Performance:** A consulta ao Supabase adiciona latência. Usar timeout de 1s; se exceder, skip silencioso
- **Volume de dados:** Cada usuário gera ~5 registros/conversa. Com 1000 usuários/mês = 5000 registros — totalmente gerenciável no plano gratuito do Supabase
