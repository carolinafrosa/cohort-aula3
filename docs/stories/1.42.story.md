# Story 1.42 — Mensagem de erro técnico no WhatsApp

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.42
**Prioridade:** Alta
**Estimativa:** S (1–2h)

---

## Descrição

Quando o fluxo falha (timeout Oracle, erro Groq, LLM fora do ar, etc.), o usuário simplesmente não recebe resposta. Não há feedback algum.

A solução é configurar um **Error Workflow** dedicado no n8n que envia uma mensagem de desculpa pelo WhatsApp sempre que ocorrer qualquer erro no fluxo principal.

---

## Como implementar no n8n UI

### Passo 1 — Criar o workflow `Projeta SC - Error Handler`

Criar um **novo workflow** separado com:

**Nó 1: `Error Trigger`** (tipo: n8n-nodes-base.errorTrigger)
- Gatilho automático ao ocorrer erro em qualquer workflow que o referencie

**Nó 2: `ExtraiRemetente`** (Code node)
```javascript
// O Error Trigger recebe o contexto da execução que falhou.
// O input original (webhook) fica em execution.data.resultData
const exec = $input.item.json;

// Tenta extrair o número do usuário a partir dos dados da execução
let numero = '';
try {
  const nodes = exec?.execution?.data?.resultData?.runData;
  // Percorre todos os nós buscando o remoteJid no payload do webhook
  if (nodes) {
    for (const nodeData of Object.values(nodes)) {
      const items = nodeData?.[0]?.[0]?.data?.main?.[0];
      if (!items) continue;
      for (const item of items) {
        const jid =
          item?.json?.body?.data?.key?.remoteJid ||
          item?.json?.body?.data?.message?.key?.remoteJid;
        if (jid) { numero = jid; break; }
      }
      if (numero) break;
    }
  }
} catch (_) {}

return [{ json: { numero, workflow: exec?.workflow?.name || 'Projeta SC' } }];
```

**Nó 3: `EnviaErroParcial`** (IF node)
- Condição: `numero` não está vazio
- Saída true → nó de envio
- Saída false → Stop (sem número, não tem como enviar)

**Nó 4: `RetornoErroTecnico`** (HTTP Request node)
- URL: `https://n8n-evolution-api.lkpafu.easypanel.host/message/sendText/Projeta_SC`
- Método: POST
- Auth: Header Auth (mesma credencial `httpHeaderAuth`)
- Body (JSON):
```json
{
  "number": "={{ $json.numero }}",
  "options": { "delay": 0, "presence": "composing" },
  "textMessage": {
    "text": "Ops! 😕 Estamos passando por um problema técnico.\n\nTente novamente em alguns instantes. Se o problema persistir, entre em contato com a Secretaria de Infraestrutura."
  }
}
```

### Passo 2 — Referenciar no fluxo principal

No workflow **Projeta SC** (fluxo principal):
1. Abrir **Settings** (ícone de engrenagem)
2. Campo **Error Workflow** → selecionar `Projeta SC - Error Handler`
3. Salvar

A partir daí, qualquer falha não tratada no fluxo principal dispara automaticamente o Error Handler.

### Passo 3 — (Opcional) Tratamento específico no Oracle

Para erros esperados (timeout Oracle), adicionar **saída de erro** no nó `ConsultaProjetos`:
- Ativar "Continue on Error" no nó
- Conectar a saída de erro a um Code node `TrataErroOracle` que retorna a mensagem diretamente

---

## Acceptance Criteria

- [ ] Quando qualquer nó do fluxo falha, o usuário recebe a mensagem de erro técnico em até 5 segundos
- [ ] A mensagem usa o número correto (quem enviou a mensagem original)
- [ ] Se o número não puder ser extraído, o erro é registrado silenciosamente sem travar
- [ ] Erros são visíveis nos logs de execução do n8n para diagnóstico
