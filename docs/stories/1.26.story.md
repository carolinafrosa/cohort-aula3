# Story 1.26 — Clone Reformatter LLM: Humanização da Voz nas Respostas

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.26
**Prioridade:** Alta
**Estimativa:** M (3–5h de edição no n8n)

---

## Descrição

Os resultados do banco Oracle são formatados por Code nodes e enviados diretamente ao WhatsApp. O texto resultante é correto mas mecânico — lista de campos, números brutos, sem fluidez conversacional.

Esta story adiciona um **nó reformatter LLM** como última etapa antes de cada envio ao WhatsApp. Este nó recebe o texto formatado atual e um prompt de sistema com a persona do bot (definida na Story 1.24), e reescreve a mensagem na voz do personagem sem alterar os dados.

```
[Texto bruto do Code node]
    → [Reformatter LLM]
    → [Texto humanizado]
    → [Evolution API → WhatsApp]
```

**Valor:** Maior impacto de humanização com menor risco. O reformatter não toca em dados nem em lógica — apenas na voz. É a única mudança que transforma "dados" em "conversa". ROI 3.0.

---

## Workflow de Desenvolvimento

```
1. Definir prompt de sistema do reformatter (persona do bot, regras de tom, o que NÃO alterar)
2. Importar docs/flow/projeta-sc.json no n8n
3. Para cada nó de formatação (FormataProjeto, FormataEntregas, FormataValores,
   FormadaContratos, FormataDetalheContrato, FormataRefinamento):
   a. Inserir nó HTTP Request (Groq) APÓS o Code node de formatação
   b. Passar o texto formatado + prompt de sistema
   c. Retornar texto reescrito
4. Conectar saída do reformatter ao nó de resposta WhatsApp correspondente
5. Testar: comparar texto antes/depois — dados preservados, voz humanizada
6. Exportar e substituir docs/flow/projeta-sc.json
7. Commitar
```

---

## Acceptance Criteria

### AC-1: Nó reformatter inserido nos fluxos de formatação
- [ ] Após `FormataProjeto`, `FormataEntregas`, `FormataValores`, `FormadaContratos`, `FormataDetalheContrato` e `FormataRefinamento`, existe um nó HTTP Request que chama o Groq com o texto gerado pelo Code node
- [ ] O nó usa o modelo `llama-3.1-8b-instant` (ou equivalente de baixa latência disponível no Groq)

### AC-2: Prompt de sistema da persona
- [ ] O prompt de sistema define: nome do bot, tom (próximo/respeitoso), uso moderado de emojis, proibição de inventar dados
- [ ] O prompt inclui explicitamente: *"Nunca altere valores monetários, nomes de projetos, datas ou números. Apenas reescreva o estilo e o tom."*

### AC-3: Dados preservados
- [ ] Após reformatação, todos os valores numéricos (datas, R$, percentuais) são idênticos ao texto original
- [ ] Todos os nomes de projetos e municípios são preservados exatamente

### AC-4: Graceful degradation
- [ ] Se o Groq falhar (timeout/erro), o fluxo envia o texto original formatado sem reformatação — sem crash, sem mensagem de erro ao usuário

### AC-5: Latência aceitável
- [ ] O reformatter adiciona no máximo 2s ao tempo de resposta total
- [ ] Usar modelo de baixa latência do Groq (não usar GPT-4 ou equivalente pesado)

## Cenários de Teste

| Cenário | Ação | Resultado esperado |
|---------|------|--------------------|
| Resultado de projeto | Buscar qualquer projeto | Dados corretos + linguagem fluída |
| Resultado de valores | Selecionar "Valores do projeto" | R$, datas e % preservados, texto humanizado |
| Groq timeout | Simular falha do Groq | Texto original enviado sem erro |
| Dados sensíveis | Verificar que R$ e nomes não foram alterados | Valores idênticos ao texto pré-reformatter |

## Escopo

**IN:**
- Nó reformatter LLM após cada Code node de formatação de resultado
- Prompt de sistema com persona (derivado da Story 1.24)
- Graceful degradation

**OUT:**
- Reformatação de mensagens estáticas (menus, saudações — coberto pela Story 1.24)
- Alteração de lógica de consulta ou roteamento
- Tradução ou alteração de idioma

---

## Dependências

- Story 1.24 (persona com identidade) — o prompt de sistema do reformatter depende do nome e tom definidos lá. Pode ser implementada em paralelo se a persona for definida antes.
- Groq API Key disponível e funcional no fluxo

---

## Riscos

- **Groq alucina dados:** O modelo pode "corrigir" valores que considera errados — o prompt deve ser rígido em proibir alterações de dados. Testar com valores não-redondos (R$ 1.234.567,89)
- **Latência composta:** Se o Oracle já está lento, adicionar 1–2s do Groq pode ser perceptível. Monitorar tempo total no n8n execution log
