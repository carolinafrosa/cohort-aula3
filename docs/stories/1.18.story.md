# Story 1.18 — Corrigir ORDER BY nas Consultas de Contratos

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.18
**Prioridade:** Alta
**Estimativa:** XS (1h de edição no n8n)

---

## Descrição

Duas queries de contratos usam `ROWNUM` sem `ORDER BY`:

```sql
-- PreparaContratos (nó Code)
WHERE PROJETO_ID = {id} AND ROWNUM < 16

-- ConsultaContratos1 (nó Oracle - parâmetro direto)
WHERE PROJETO_ID = {{ $json.PROJETO_ID }} AND ROWNUM <= 15
```

No Oracle, `ROWNUM` é atribuído **antes** da ordenação. Sem `ORDER BY`, o banco retorna as 15 linhas em ordem de bloco físico — que muda com inserções, atualizações e reorganizações de tablespace. O cidadão pode receber contratos diferentes para o mesmo projeto em consultas distintas, sem nenhuma ordem lógica.

Além disso, `ROWNUM < 16` e `ROWNUM <= 15` são semanticamente idênticos mas inconsistentes — um risco de manutenção.

**Valor:** Contratos exibidos sempre em ordem determinística (mais recentes primeiro), eliminando comportamento não-determinístico que confunde usuários e dificulta debugging.

## Acceptance Criteria

### AC-1: PreparaContratos — ORDER BY antes de ROWNUM

- [ ] A query segue o padrão Oracle 11g de subquery-com-ORDER BY para limitar com ordenação:

```sql
SELECT * FROM (
    SELECT NUMERO_CONTRATO AS NUMERO, OBJETO, SITUACAO,
           TOTAL_CONTRATADO, VL_EXECUTADO, VL_PAGO,
           PC_EXECUTADO, DT_INICIO, DT_FIM,
           CONTRATADA, TIPO_CONTRATO
    FROM VW_CONTRATO
    WHERE PROJETO_ID = {id}
    ORDER BY DT_INICIO DESC
) WHERE ROWNUM <= 15
```

- [ ] `ROWNUM < 16` substituído por `ROWNUM <= 15`
- [ ] A construção JavaScript em `PreparaContratos` gera exatamente esse SQL

### AC-2: ConsultaContratos1 — mesmo padrão aplicado

- [ ] O campo `query` do nó Oracle `ConsultaContratos1` usa subquery com `ORDER BY DT_INICIO DESC` antes do `ROWNUM`
- [ ] `ROWNUM <= 15` (consistente com AC-1)

### AC-3: Ordenação determinística verificada

- [ ] Para um projeto com mais de 1 contrato, os contratos são exibidos do mais recente (`DT_INICIO` mais alto) para o mais antigo
- [ ] Duas consultas consecutivas ao mesmo projeto retornam contratos na mesma ordem

### AC-4: Sem regressão

- [ ] `FormadaContratos` continua funcionando corretamente (recebe os mesmos campos, agora ordenados)
- [ ] Projetos com 0 contratos: mensagem de erro suavizado do AC-3 da story 1.10 é exibida

## Escopo

**IN:**
- Refatoração da query em `PreparaContratos` (nó Code)
- Refatoração da query em `ConsultaContratos1` (nó Oracle, campo `query`)
- Padronização de `ROWNUM <= 15` em ambos

**OUT:**
- Alteração no número máximo de contratos retornados (continua 15)
- Alteração na lógica de exibição em `FormadaContratos`
- Alteração no campo de ordenação (se `DT_INICIO` não existir na view, consultar alternativa — ver Riscos)

## Riscos

- **DT_INICIO nulo:** Se alguns contratos não têm `DT_INICIO` preenchido, eles aparecerão no final da lista (NULL LAST no Oracle é o padrão para DESC). Comportamento aceitável.
- **Nome da coluna de data:** A view `VW_CONTRATO` expõe `DT_INICIO` e `DT_FIM` — confirmar que esses nomes existem antes de aplicar. Se o nome for diferente, usar a coluna de data disponível.
