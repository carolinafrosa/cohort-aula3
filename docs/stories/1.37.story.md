# Story 1.37 — Feedback Loop para Melhoria Contínua dos Prompts

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.37
**Prioridade:** Baixa
**Estimativa:** M (3–5h)

---

## Descrição

Os prompts do `GroqClassificador` e do `InterpretaConsulta` foram escritos uma vez e nunca atualizados com base em exemplos reais de uso. O bot aprende com os exemplos do prompt de sistema, mas esses exemplos são estáticos — não refletem as perguntas reais que os cidadãos fazem.

Esta story implementa um **feedback loop passivo**: armazenar pares (pergunta → intent classificada) no Supabase, permitindo que periodicamente os melhores exemplos sejam identificados e incorporados aos prompts como few-shot examples.

**Não é aprendizado automático** — é um pipeline semi-manual: os dados são coletados automaticamente, mas a revisão e atualização dos prompts é feita por humano (ou @dev).

**Valor:** Com 100 exemplos reais de uso, os prompts ficam significativamente mais precisos do que com exemplos inventados. ROI crescente com o tempo de operação.

---

## Workflow de Desenvolvimento

```
1. Criar tabela no Supabase:
   CREATE TABLE prompt_feedback (
     id SERIAL PRIMARY KEY,
     raw_message TEXT NOT NULL,
     classified_intent TEXT,
     confidence NUMERIC,
     result_count INT,
     was_helpful BOOLEAN DEFAULT NULL,  -- null = não avaliado
     created_at TIMESTAMPTZ DEFAULT NOW()
   );

2. Importar docs/flow/projeta-sc.json no n8n
3. Após AplicaClassificacao, inserir nó "SalvaClassificacao" (HTTP Request → Supabase):
   - Salvar: raw_message, classified_intent, confidence (se Story 1.28 implementada)
4. Após retorno de resultado, atualizar result_count no registro criado
5. (Opcional) Adicionar botão de feedback: ao final da resposta, perguntar
   "Isso foi útil? 👍 / 👎" e armazenar was_helpful

6. Criar view no Supabase para identificar classificações problemáticas:
   SELECT raw_message, classified_intent, count(*)
   FROM prompt_feedback
   WHERE result_count = 0 OR confidence < 0.7
   GROUP BY 1, 2 ORDER BY count DESC

7. Documentar processo de atualização de prompts com base nos dados
8. Exportar e substituir docs/flow/projeta-sc.json
9. Commitar
```

## Acceptance Criteria

### AC-1: Coleta automática de classificações
- [ ] Após cada classificação de intent pelo `GroqClassificador`, o nó `SalvaClassificacao` insere um registro em `prompt_feedback`
- [ ] Campos obrigatórios: `raw_message`, `classified_intent`, `created_at`
- [ ] Se Story 1.28 estiver implementada: incluir `confidence`

### AC-2: Result count atualizado
- [ ] Após retorno do Oracle, o registro de feedback é atualizado com `result_count` (0 = busca sem resultado)

### AC-3: View de análise criada
- [ ] View ou query SQL no Supabase que identifica: classificações com result_count = 0, classified_intents mais frequentes, mensagens com baixa confidence

### AC-4: (Opcional) Feedback explícito do usuário
- [ ] Se implementado, ao final de resultados, o bot pergunta "Isso ajudou? 1-Sim / 2-Não"
- [ ] A resposta é armazenada no campo `was_helpful` do registro correspondente

### AC-5: Processo documentado
- [ ] Processo de revisão e atualização de prompts documentado no Change Log ou em `docs/`
- [ ] Inclui: como acessar os dados, como identificar problemas, como atualizar o prompt no n8n

---

## Riscos

- **Volume de dados:** Com uso intenso, a tabela pode crescer rápido → adicionar índice em `created_at` e política de retenção (ex: 90 dias)
- **PII acidental:** Mensagens de usuários podem conter dados pessoais (nome, endereço) — revisar política antes de coletar. O `raw_message` é o campo mais sensível.
