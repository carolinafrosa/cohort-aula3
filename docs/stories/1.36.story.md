# Story 1.36 — Link de Relatório Dinâmico para Projetos com Muitos Contratos

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.36
**Prioridade:** Baixa
**Estimativa:** M (4–6h)

---

## Descrição

Projetos grandes (infraestrutura viária, habitação em escala) podem ter dezenas de contratos. O bot atual tenta exibir todos via WhatsApp, resultando em uma sequência interminável de mensagens que o usuário não consegue navegar.

Esta story implementa um **link de relatório dinâmico**: quando um projeto tem mais de N contratos (threshold configurável, ex: 5), em vez de listar todos no WhatsApp, o bot gera um link para uma página web simples com o relatório completo.

**Implementação sugerida:** n8n gera um arquivo JSON e o armazena no Supabase Storage, retornando uma URL pública temporária (válida por 24h). A página HTML é um template estático hospedado separadamente.

**Valor:** Resolve o problema de "parede de texto" para projetos complexos e melhora a legibilidade do histórico de conversa no WhatsApp.

---

## Workflow de Desenvolvimento

```
1. Importar docs/flow/projeta-sc.json no n8n
2. Em FormadaContratos: verificar count de contratos retornados
   - Se <= 5: exibir normalmente (comportamento atual)
   - Se > 5: ativar branch de relatório

3. Para o branch de relatório:
   a. Criar nó "GeraRelatorio" (Code): montar JSON estruturado com todos os dados do projeto + contratos
   b. Criar nó "PublicaRelatorio" (HTTP Request → Supabase Storage):
      - Upload do JSON em bucket público com UUID como nome
      - URL: https://{project}.supabase.co/storage/v1/object/public/reports/{uuid}.json
   c. Criar nó "EnviaLink" (HTTP Request → Evolution API):
      - Mensagem: "Esse projeto tem [N] contratos — preparei um relatório completo: [URL]"
      - Incluir link clicável

4. Criar página HTML estática (template) que lê o JSON da URL e renderiza
   (hospedar no GitHub Pages ou similar)

5. Configurar expiração: webhook ou cron que remove arquivos com > 24h do Storage

6. Testar com projeto que tem muitos contratos
7. Exportar e commitar
```

---

## Acceptance Criteria

### AC-1: Threshold configurável
- [ ] O valor de corte (padrão: 5 contratos) é definido como constante no Code node, facilmente editável

### AC-2: Branch de relatório ativado acima do threshold
- [ ] Quando `ConsultaContratos` retorna mais de 5 registros, o fluxo desvia para geração de relatório
- [ ] Quando retorna ≤ 5, exibe normalmente (comportamento atual preservado)

### AC-3: JSON do relatório publicado no Supabase Storage
- [ ] O arquivo JSON é gerado com todos os contratos e dados do projeto
- [ ] URL pública gerada e acessível por 24h

### AC-4: Link enviado ao usuário via WhatsApp
- [ ] Mensagem com texto: *"Esse projeto tem [N] contratos. Preparei um relatório completo para você: [URL]"*
- [ ] O link é clicável no WhatsApp (URL válida)

### AC-5: Página de relatório legível
- [ ] O template HTML exibe os contratos de forma estruturada (tabela HTML simples, sem framework externo)
- [ ] Funciona em mobile (responsivo via meta viewport + CSS básico sem bibliotecas externas)
- [ ] Hospedagem no GitHub Pages do mesmo repositório (`docs/report-template/index.html`) — sem necessidade de serviço adicional
- [ ] Campos obrigatórios exibidos: nome do projeto, município, valor planejado, número do contrato, contratada, valor do contrato, status

## Cenários de Teste

| Cenário | Ação | Resultado esperado |
|---------|------|--------------------|
| Projeto com 3 contratos | Selecionar contratos | Lista normal no WhatsApp |
| Projeto com 10 contratos | Selecionar contratos | Link de relatório enviado |
| Link acessado | Clicar na URL enviada | Página com todos os contratos |
| Link expirado | Acessar URL após 24h | Página de expiração ou 404 |

---

## Escopo

**IN:**
- Branch condicional em `FormadaContratos` por count de contratos
- Geração de JSON e upload no Supabase Storage
- Link enviado via WhatsApp
- Template HTML estático de relatório

**OUT:**
- Geração de PDF
- Autenticação para acesso ao relatório
- Histórico de relatórios gerados
- Relatório para outras entidades além de contratos

---

## Dependências

- Story 1.31 (Supabase configurado) — recomendado mas não bloqueante se Supabase Storage for configurado de forma independente
- `SUPABASE_URL` e `SUPABASE_SERVICE_ROLE_KEY` disponíveis no n8n (para escrita no Storage)
- Hospedagem para o template HTML (GitHub Pages, Vercel, ou similar)

---

## Riscos

- **Supabase Storage não configurado:** Se o bucket não existir ou a SERVICE_ROLE_KEY não tiver permissão de escrita, a feature falha → graceful fallback: exibir os primeiros 5 contratos e avisar que há mais
- **URL de relatório expirada em conversa longa:** Usuário que recebe o link e tenta acessar após 24h recebe 404 → mitigar com mensagem clara sobre expiração
