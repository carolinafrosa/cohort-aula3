# Story 1.23 — Simular Digitação e Fragmentar Respostas Longas

**Status:** InProgress
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.23
**Prioridade:** Alta
**Estimativa:** XS (1–2h de edição no n8n)

---

## Descrição

Atualmente o bot envia todas as respostas em uma única mensagem de texto longo, sem sinalização prévia de que está processando. No WhatsApp, isso cria percepção de robô — o usuário vê silêncio seguido de um dump de informação.

Esta story implementa dois mecanismos complementares:

1. **`sendPresence(typing)`** — chamar o endpoint de presença da Evolution API antes de cada resposta, simulando que alguém está digitando
2. **Fragmentação de mensagens longas** — dividir respostas com mais de 300 caracteres em 2–3 partes com delay de 1.2s entre elas

**Valor:** Mudança mais visceral de "parece humano" — o indicador de digitação e as mensagens progressivas são o padrão das conversas humanas no WhatsApp. ROI 4.0 (maior da sessão de brainstorming).

---

## Workflow de Desenvolvimento

```
1. Importar docs/flow/projeta-sc.json no n8n
2. Para cada nó de resposta (RetornoBoasVindas, RetornoProjeto, RetornaMensagem,
   RetornoReinicio, RespondePerguntas):
   a. Adicionar chamada HTTP Request para sendPresence ANTES do envio da mensagem
   b. Se o texto > 300 chars, dividir em partes (respeitar quebras de linha)
3. Inserir nó Wait (1200ms) entre fragmentos de uma mesma resposta
4. Testar no WhatsApp real — confirmar indicador de digitação e fragmentação visível
5. Exportar e substituir docs/flow/projeta-sc.json
6. Commitar
```

---

## Acceptance Criteria

### AC-1: Indicador de digitação ativo
- [x] Antes de qualquer resposta enviada, a Evolution API recebe `POST /chat/sendPresence` com `presence: "composing"` para a instância `Projeta_SC`
- [ ] O usuário no WhatsApp vê "digitando..." antes da mensagem aparecer (validar no WhatsApp real)

### AC-2: Fragmentação de respostas longas
- [x] Respostas com mais de 300 caracteres são divididas em partes de no máximo 280 caracteres, respeitando quebras de linha (nunca cortar palavra ou emoji no meio)
- [x] Cada fragmento é enviado com delay de 1200ms entre eles
- [x] O `sendPresence` é chamado antes de cada fragmento

### AC-3: Respostas curtas não são afetadas
- [x] Mensagens com até 300 caracteres são enviadas normalmente, sem fragmentação nem delay adicional

### AC-4: Conteúdo preservado
- [x] A concatenação de todos os fragmentos é idêntica ao texto original
- [x] Nenhum caractere é perdido ou duplicado

## Cenários de Teste

| Cenário | Ação | Resultado esperado |
|---------|------|--------------------|
| Resposta curta (menu) | Enviar "oi" | Digitando... → mensagem única |
| Resposta longa (projeto) | Buscar projeto com muitos campos | Digitando... → 2–3 mensagens sequenciais |
| Lista de contratos | Selecionar opção de contratos | Fragmentação visível no WhatsApp |
| Mensagem de reinício | Digitar "menu" | Indicador de digitação + mensagem única |

---

## Escopo

**IN:**
- Chamada `sendPresence` antes de todos os nós de resposta WhatsApp
- Fragmentação automática de mensagens > 300 chars
- Delay de 1.2s entre fragmentos

**OUT:**
- Alteração do conteúdo das mensagens
- Mudança de lógica de roteamento ou classificação
- Adição de novo conteúdo informativo

---

## Dependências

- Evolution API deve suportar endpoint `sendPresence` na instância `Projeta_SC` (verificar antes de implementar)

---

## Riscos

- **`sendPresence` indisponível na versão atual da Evolution API:** Se o endpoint não existir, omitir AC-1 e implementar apenas a fragmentação
- **Emojis compostos cortados:** Emojis de múltiplos codepoints (bandeiras, famílias) podem ser cortados na fragmentação — validar com WhatsApp real
