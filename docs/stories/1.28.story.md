# Story 1.28 — Confidence Score e Confirmação Conversacional de Intenção

**Status:** InProgress
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.28
**Prioridade:** Alta
**Estimativa:** M (3–5h de edição no n8n)

---

## Descrição

O `GroqClassificador` retorna uma intenção (ex: "buscar_projeto", "ver_valores") mas não expõe um nível de confiança. Quando a mensagem do usuário é ambígua ("me fala sobre aquele projeto"), o fluxo tenta adivinhar e frequentemente processa a intenção errada, gerando respostas irrelevantes.

Esta story modifica o classificador para retornar JSON estruturado com campo `confidence`, e adiciona um nó de confirmação que intervém quando a confiança é baixa.

```
Mensagem ambígua
    → GroqClassificador retorna { intent, confidence: 0.55 }
    → VerificaConfianca: 0.55 < 0.75 → ramo de confirmação
    → Bot pergunta: "Você quer [X] ou [Y]? (1 ou 2)"
    → Usuário escolhe → fluxo normal
```

**Valor:** Elimina a principal causa de "respondeu errado" — que é processar intenção ambígua sem confirmar. ROI 2.0, mas impacto de assertividade é direto.

---

## Workflow de Desenvolvimento

```
1. Importar docs/flow/projeta-sc.json no n8n
2. Modificar prompt do GroqClassificador:
   - Retorno atual: string com intent
   - Novo retorno: JSON { "intent": "buscar_projeto", "confidence": 0.87, "alternatives": ["ver_valores"] }
3. Modificar AplicaClassificacao:
   - Parse do JSON retornado
   - Extrair confidence e alternatives
4. Criar nó Code "VerificaConfianca":
   - Se confidence >= 0.75: passa para RoteiaClassificacao normalmente
   - Se confidence < 0.75: redireciona para confirmação
5. Criar nó de confirmação (Code + HTTP Request):
   - Monta mensagem com as 2 opções detectadas
   - Aguarda resposta do usuário (1 ou 2)
6. Reconectar fluxo após confirmação para RoteiaClassificacao
7. Testar com mensagens ambíguas
8. Exportar e substituir docs/flow/projeta-sc.json
9. Commitar
```

## Acceptance Criteria

### AC-1: GroqClassificador retorna JSON com confidence
- [x] Prompt atualizado para retornar `{ "tipo": "...", "confidence": 0.0-1.0, "alternatives": [...] }`
- [x] `AplicaClassificacao` parse defensivo: JSON inválido → confidence=1.0 (sem confirmação)

### AC-2: Nó VerificaConfianca opera corretamente
- [x] Mensagens com confidence >= 0.70 (threshold configurável) prosseguem sem interrupção
- [x] Mensagens com confidence < 0.70 desviam para ramo de confirmação

### AC-3: Confirmação conversacional apresenta alternativas
- [x] Mensagem de confirmação exibe as 2 intenções como opções numeradas (1️⃣ / 2️⃣)
- [x] Exemplo: *"Hm, não tenho certeza... 1️⃣ Buscar um projeto / 2️⃣ Fazer uma pergunta. Qual?"*

### AC-4: Fluxo normal após confirmação
- [x] Estado `aguardando_confirmacao` salvo no staticData com TTL de 3 minutos
- [x] ProcessaMensagem resolve a escolha (1 ou 2) na próxima mensagem (patch documentado)
- [x] Confirmação expira automaticamente após 3 min sem resposta

### AC-5: Fallback para intenções únicas
- [x] Sem alternatives → passa sem confirmação mesmo com confidence baixo

## Escopo

**IN:**
- Modificação do prompt do `GroqClassificador` para retornar JSON com confidence
- Nó `VerificaConfianca` com threshold 0.75
- Ramo de confirmação conversacional

**OUT:**
- Alteração do `RoteiaClassificacao` ou dos nós subsequentes
- Múltiplos níveis de confirmação (apenas 1 nível)
- Mudança no modelo Groq usado (manter o mesmo)

---

## Dependências

- Story 1.24 (persona) — a mensagem de confirmação deve usar a voz do bot definida lá

---

## Riscos

- **Groq não retorna JSON válido:** O modelo pode não seguir o formato JSON mesmo com instrução → adicionar parse defensivo com fallback para string simples e confidence = 1.0 (trata como certeza)
- **Threshold muito restritivo:** 0.75 pode gerar confirmações excessivas para mensagens claras → ajustar threshold após observação real (começar com 0.70)
