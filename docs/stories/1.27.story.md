# Story 1.27 — Skill de Normalização Geográfica e Monetária de SC

**Status:** InProgress
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.27
**Prioridade:** Alta
**Estimativa:** S (2–3h de edição no n8n)

---

## Descrição

Dois tipos de entrada do usuário chegam ao `InterpretaConsulta` em formato que o LLM não consegue resolver para o banco Oracle:

1. **Apelidos de municípios:** "Floripa" → "Florianópolis", "Blumenal" → "Blumenau", "Grande Fpolis" → conjunto de municípios
2. **Valores monetários coloquiais:** "2 bilhões", "R$ 500 mi", "meio milhão" → valores numéricos para filtros de `VALORPLANEJADO`

Esta story cria um nó `NormalizaEntrada` (Code node) inserido entre `ProcessaMensagem` e `InterpretaConsulta`, que aplica as normalizações antes que o LLM tente interpretar a consulta.

**Valor:** Erros de busca por apelido de município são a principal causa de "não encontrei nada" quando o dado existe no banco. ROI 4.0 — maior ganho de assertividade com menor esforço da sessão de brainstorming.

---

## Workflow de Desenvolvimento

```
1. Levantar os 40 apelidos mais usados de municípios de SC (pesquisa + senso comum)
2. Definir conversões monetárias: "bilhão" = 1_000_000_000, "milhão" = 1_000_000, etc.
3. Importar docs/flow/projeta-sc.json no n8n
4. Criar nó Code "NormalizaEntrada":
   - Input: mensagem do usuário (text)
   - Processo: substituir apelidos por nome oficial; converter expressões monetárias
   - Output: texto normalizado
5. Inserir NormalizaEntrada entre ProcessaMensagem e InterpretaConsulta
6. Testar com casos reais (Floripa, blumenal, 2bi, etc.)
7. Exportar e substituir docs/flow/projeta-sc.json
8. Commitar
```

## Acceptance Criteria

### AC-1: Normalização de apelidos de municípios
- [x] Dicionário com no mínimo 30 apelidos de municípios de SC mapeados para o nome oficial conforme o banco Oracle
- [x] Normalização é case-insensitive ("floripa", "Floripa", "FLORIPA" → "Florianópolis")
- [x] Apelidos de regiões são expandidos para lista de municípios: "Grande Fpolis" → "Florianópolis, São José, Palhoça, Biguaçu"

### AC-2: Normalização de valores monetários
- [x] Expressões como "2 bilhões", "R$ 500 mi", "500 mil", "meio bilhão" são convertidas para valor numérico antes de chegar ao LLM
- [x] O LLM recebe o valor numérico limpo: "projetos acima de R$ 500.000.000"

### AC-3: Texto não-geocoded passa sem alteração
- [x] Mensagens que não contêm apelidos ou valores coloquiais passam pelo nó sem modificação

### AC-4: Nó posicionado corretamente
- [ ] `NormalizaEntrada` inserido no n8n entre `PreparaConsulta` e `InterpretaConsulta`
- [ ] O texto normalizado (não o original) é passado ao LLM de interpretação (validar no n8n)

## Escopo

**IN:**
- Dicionário de apelidos de municípios de SC (≥30 entradas)
- Conversão de expressões monetárias coloquiais
- Nó Code inserido antes do InterpretaConsulta

**OUT:**
- Normalização de outros tipos de entrada (datas, categorias, nomes de projetos)
- Atualização automática do dicionário via banco de dados
- Interface de administração do dicionário

## Dependências

## Riscos

- **Apelido ambíguo:** "Norte" pode ser bairro ou mesorregião — normalizar apenas apelidos sem ambiguidade; apelidos duvidosos passam sem alteração
- **Falso positivo:** "floripa" em nome de projeto (improvável mas possível) seria substituído incorretamente — aceitar risco dado baixíssima probabilidade
