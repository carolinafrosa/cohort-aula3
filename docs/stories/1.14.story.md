# Story 1.14 — Histórico de Conversa nos Prompts de LLM

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.14
**Prioridade:** Média
**Estimativa:** M (4–6h de edição no n8n)

---

## Descrição

Atualmente, os nós de Q&A livre (`PreparaPromptPergunta`) e refinamento (`PreparaPromptRefinamento`) enviam apenas **1 turno** de conversa para o LLM — a pergunta atual do usuário. O modelo não tem acesso às trocas anteriores da sessão:

```json
"messages": [
  { "role": "system", "content": "..." },
  { "role": "user", "content": "pergunta atual" }
]
```

Isso cria inconsistências visíveis: se o usuário perguntar "quando começa?" e depois "e termina?", o LLM da segunda pergunta não sabe que a primeira foi sobre prazo — responde sem contexto.

O ChatGPT mantém todo o histórico de conversa em `messages[]`. Esta story implementa o mesmo padrão: armazenar os últimos 4 turnos de Q&A no `staticData.contextos` e injetá-los nos prompts subsequentes.

**Valor:** Torna possível conversas encadeadas sobre o mesmo projeto — o usuário pode fazer perguntas de follow-up sem recontextualizar. É o maior salto individual em direção à experiência ChatGPT.

---

## Workflow de Desenvolvimento

```
1. Importar docs/flow/projeta-sc.json no n8n (Settings → Import)
2. Editar o nó ProcessaMensagem:
   - Adicionar campo historico_qa: [] ao objeto de contexto inicial
3. Editar o nó AplicaClassificacao:
   - Quando tipo = 'pergunta_livre', incluir historico_qa no objeto retornado
4. Editar o nó PreparaPromptPergunta:
   - Ler historico_qa do input
   - Injetar os turnos anteriores no array messages[] antes da pergunta atual
   - Após montar o request_body, NÃO salvar aqui (o salvar é no próximo passo)
5. Criar novo nó Code após FormataRespostaLivre: "SalvaHistoricoQA"
   - Lê a resposta do LLM e a pergunta do usuário
   - Appende 2 entradas ao historico_qa: {role: "user"} e {role: "assistant"}
   - Mantém máximo de 4 turnos (8 entradas) — descarta os mais antigos
   - Salva no staticData.contextos[remetente].historico_qa
6. Testar com perguntas encadeadas sobre um projeto
7. Exportar e substituir docs/flow/projeta-sc.json
8. Commitar
```

## Acceptance Criteria

### AC-1: Estrutura de contexto atualizada
- [ ] Campo `historico_qa` adicionado ao objeto de contexto em `ProcessaMensagem` com valor inicial `[]`
- [ ] Ao resetar contexto (reinício, timeout), `historico_qa` também é resetado para `[]`

### AC-2: AplicaClassificacao propaga histórico
- [ ] Quando `tipo === 'pergunta_livre'`, o objeto retornado inclui `historico_qa` vindo do contexto

### AC-3: PreparaPromptPergunta injeta histórico no messages[]
- [ ] Os turnos anteriores do `historico_qa` são inseridos antes do turno atual no array `messages[]`
- [ ] O turno atual do usuário é sempre o último item do array
- [ ] Se `historico_qa` estiver vazio, o comportamento é idêntico ao atual (sem regressão)
- [ ] Máximo de 4 turnos anteriores injetados (para não exceder o contexto do modelo)

**Estrutura esperada do messages[] com histórico:**
```json
[
  { "role": "system", "content": "..." },
  { "role": "user", "content": "qual o prazo desse projeto?" },
  { "role": "assistant", "content": "O projeto tem prazo de conclusão para dezembro de 2025." },
  { "role": "user", "content": "e o valor?" },
  { "role": "assistant", "content": "O valor planejado é R$ 45 milhões." },
  { "role": "user", "content": "já foi pago alguma coisa?" }
]
```

### AC-4: Nó SalvaHistoricoQA criado após FormataRespostaLivre
- [ ] Nó Code `SalvaHistoricoQA` inserido entre `FormataRespostaLivre` e `RespondePerguntas`, reconectando ambos
- [ ] Lê pergunta do usuário via `$('AplicaClassificacao').first().json.pergunta` (campo `pergunta` propagado pelo classificador para `tipo: pergunta_livre`)
- [ ] Lê resposta do LLM via `$('FormataRespostaLivre').first().json.mensagem_retorno`
- [ ] Preserva os campos `mensagem_retorno` e `remetente` no output para que `RespondePerguntas` os receba inalterados
- [ ] Adiciona `{ role: "user", content: pergunta }` e `{ role: "assistant", content: resposta }` ao array
- [ ] Descarta turnos mais antigos quando o array ultrapassar 8 entradas (4 turnos de ida e volta)
- [ ] Salva o array atualizado em `staticData.contextos[remetente].historico_qa`
- [ ] Propaga o objeto para o próximo nó sem modificar outros campos

### AC-5: Sem regressão no fluxo
- [ ] Buscas de projeto funcionam normalmente (histórico não afeta o fluxo de busca)
- [ ] Refinamento de busca não é afetado
- [ ] Classificação de intents continua correta

## Cenários de Teste

| Cenário | Ação | Resultado esperado |
|---------|------|--------------------|
| Pergunta encadeada | Selecionar projeto → "qual o prazo?" → "e o valor?" | Segunda resposta referencia o contexto da primeira |
| Follow-up implícito | "quando começa?" → "e termina?" | LLM entende que "e termina?" se refere ao prazo de término |
| Reset de histórico | Fazer perguntas → digitar "menu" → fazer pergunta | Histórico limpo — LLM não referencia conversa anterior |
| Timeout de histórico | Fazer perguntas → aguardar 16min → nova pergunta | Histórico limpo após timeout |
| Sem histórico | Primeira pergunta sobre projeto | Comportamento idêntico ao atual (sem regressão) |
| Overflow de turnos | Fazer 6 perguntas seguidas | Apenas os últimos 4 turnos são mantidos |

## Escopo

**IN:**
- Adição de `historico_qa` ao contexto em `ProcessaMensagem`
- Propagação do histórico em `AplicaClassificacao`
- Injeção do histórico no `messages[]` em `PreparaPromptPergunta`
- Criação do nó `SalvaHistoricoQA` após `FormataRespostaLivre`
- Reset do histórico junto com o contexto (timeout e reinício)

**OUT:**
- Histórico no fluxo de refinamento (`PreparaPromptRefinamento`) — este fluxo é stateless por design
- Persistência de histórico entre sessões (apenas dentro da sessão ativa)
- Histórico de buscas (somente Q&A livre)

## Riscos

- **Tamanho do contexto:** Cada turno de histórico adiciona tokens ao prompt. Com 4 turnos, o aumento estimado é de 400–800 tokens — dentro do limite do `llama-3.3-70b-versatile` (128K tokens).
- **Novo nó no fluxo:** Adicionar `SalvaHistoricoQA` requer reconectar o nó final de Q&A. Verificar que nenhuma conexão existente seja quebrada após a inserção.
- **Referência entre nós:** O `SalvaHistoricoQA` precisa acessar a pergunta original via `$('ProcessaMensagem').first().json.pergunta` — verificar que esse campo está disponível no contexto naquele ponto do fluxo.
