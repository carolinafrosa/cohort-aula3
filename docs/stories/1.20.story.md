# Story 1.20 — Padronizar "4️⃣ Nova Busca" e Corrigir Numeração nos Sub-menus

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.20
**Prioridade:** Alta
**Estimativa:** S (2–3h de edição no n8n)

---

## Descrição

Quatro nós do fluxo deixam o usuário em dead-end: não oferecem a opção "4️⃣ Nova Busca", forçando-o a conhecer os comandos ocultos "0", "menu" ou "nova busca" para continuar navegando. Além disso, o `FormataEntregas` tem um bug de numeração no estado vazio — exibe "1️⃣ Ver Valores / 2️⃣ Ver Contratos", mas o roteador espera 2=Valores e 3=Contratos, fazendo o usuário que pressiona 1 ser direcionado para **Entregas novamente** (loop).

| Nó | Problema | Tipo |
|----|----------|------|
| `FormataProjeto` | Sem opção 4️⃣ Nova Busca | Dead-end |
| `FormataEntregas` (estado vazio) | Numeração errada (1/2 em vez de 2/3) | Bug de roteamento |
| `FormataEntregas` (estado com dados) | Sem opção 4️⃣ Nova Busca | Dead-end |
| `FormataValores` | Sem opção 4️⃣ Nova Busca | Dead-end |
| `FormataDetalheContrato` | Sem opção 4️⃣ Nova Busca; ordem 3/1/2 confusa | Dead-end + inconsistência |

**Padrão de numeração canônico** (definido em `ProcessaMensagem`):
- 1️⃣ = Entregas
- 2️⃣ = Valores
- 3️⃣ = Contratos
- 4️⃣ = Nova Busca

Todos os nós de formatação devem respeitar este padrão — omitindo a opção da tela atual, mas mantendo os números fixos.

**Valor:** Elimina dead-ends que fazem o cidadão achar que o bot travou. Corrige bug silencioso de roteamento em FormataEntregas.

## Acceptance Criteria

### AC-1: FormataProjeto — adicionar 4️⃣ Nova Busca

- [ ] A mensagem de sucesso termina com:
  ```
  1️⃣ Ver Entregas
  2️⃣ Ver Valores
  3️⃣ Ver Contratos
  4️⃣ Nova Busca
  ```
- [ ] Não há alteração no conteúdo restante da mensagem

### AC-2: FormataEntregas (estado vazio) — corrigir numeração

- [ ] O estado vazio (sem entregas encontradas) usa os números canônicos:
  ```
  2️⃣ Ver Valores
  3️⃣ Ver Contratos
  4️⃣ Nova Busca
  ```
- [ ] Não usa mais "1️⃣ Ver Valores" (estava causando loop para Entregas)

### AC-3: FormataEntregas (estado com dados) — adicionar 4️⃣ Nova Busca

- [ ] A mensagem de sucesso termina com:
  ```
  2️⃣ Ver Valores
  3️⃣ Ver Contratos
  4️⃣ Nova Busca
  ```

### AC-4: FormataValores — adicionar 4️⃣ Nova Busca

- [ ] Tanto o estado vazio quanto o estado com dados terminam com:
  ```
  1️⃣ Ver Entregas
  3️⃣ Ver Contratos
  4️⃣ Nova Busca
  ```

### AC-5: FormataDetalheContrato — reordenar e adicionar 4️⃣ Nova Busca

- [ ] A mensagem termina com as opções em ordem canônica:
  ```
  1️⃣ Ver Entregas
  2️⃣ Ver Valores
  3️⃣ Ver lista de contratos
  4️⃣ Nova Busca
  ```
- [ ] Ordem anterior (3/1/2) substituída pela ordem canônica (1/2/3/4)

### AC-6: Verificação de roteamento

- [ ] Em qualquer tela, digitar "4" aciona Nova Busca (reset de contexto)
- [ ] Em qualquer tela, digitar "1" aciona Ver Entregas (se `projeto_atual` ativo)
- [ ] Não há regressão no fluxo de contratos (seleção de contrato por número ainda funciona)

## Cenários de Teste

| Cenário | Ação | Resultado esperado |
|---------|------|--------------------|
| Dead-end em projeto | Selecionar projeto → digitar 4 | Nova busca iniciada |
| Dead-end em detalhe contrato | Ver contrato → digitar 4 | Nova busca iniciada |

| Consistência de número | Em qualquer tela → digitar 3 | Sempre vai para Contratos |

## Riscos

- **Regressão na seleção de contratos:** `ProcessaMensagem` usa número para selecionar contrato da lista. O número 1 em contexto de lista de contratos seleciona o primeiro contrato, não Ver Entregas. A prioridade está correta no código (lista primeiro, projeto depois) — verificar que a alteração nos textos não afeta esse comportamento.
- **Usuário com sessão ativa durante deploy:** Contexto salvo no `staticData` não é afetado — apenas os textos exibidos mudam.
