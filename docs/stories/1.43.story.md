# Story 1.43 — Cobertura completa de campos de busca avançada

**Epic:** 1 — Qualidade e UX do Chatbot
**Status:** Ready
**Criada por:** @analyst (Atlas)
**Data:** 2026-05-14

## Contexto

Após mapeamento completo dos campos de `VW_PROJETO_BUSCA_AVANCADA_IA`, identificamos que três campos filtráveis — **PRIORIDADE**, **SETOR** e **ASSOCIACAO** — não têm resolução fuzzy no fluxo atual. Ao contrário de ORGAO, TIPO, MUNICIPIO e PROGRAMA (que usam `encontrarExato` contra uma lista de valores reais do Oracle), esses três campos são pass-through direto: se o LLM retornar um valor com acento ou capitalização diferente do Oracle, o filtro falha silenciosamente.

A raiz do problema:
1. `ConsultaDistintos` não busca PRIORIDADE, SETOR nem ASSOCIACAO
2. `PreparaConsulta` não os extrai para o cache `filtrosDistintos`
3. `AplicaFiltrosResolvidos` não aplica `encontrarExato` para eles — usa pass-through

O padrão correto já existe para PROGRAMA. Esta story replica esse padrão para os três campos faltantes.

## Campos mapeados e seus valores Oracle confirmados

| Campo | Valores Oracle | Match em MontaBusca |
|---|---|---|
| PRIORIDADE | `Baixa`, `Média`, `Alta` | `= trNorm(...)` exact |
| SETOR | desconhecido (LIKE funciona) | `LIKE` |
| ASSOCIACAO | ex: `AMAUC`, `AMREC`, `GRANFPOLIS`, `AMEOSC`, `AMMVI` | `LIKE` |

## Acceptance Criteria

- [ ] AC-1: Usuário que digitar "prioridade alta" ou "alta prioridade" tem `campos.prioridade = "Alta"` resolvido exatamente contra a lista Oracle
- [ ] AC-2: Usuário que digitar "setor saúde" ou "educação" tem `campos.setor` resolvido via fuzzy match (normalização de acentos + substring) contra `distintos.setores`
- [ ] AC-3: Usuário que digitar "AMAUC" ou "amrec" tem `campos.associacao` resolvido via fuzzy match contra `distintos.associacoes`
- [ ] AC-4: Campos com fuzzy resolution bem-sucedida registram `campos_resolvidos.{campo} = true`
- [ ] AC-5: Campos sem match na lista Oracle continuam como pass-through (fallback LIKE), com `campos_resolvidos.{campo} = false`
- [ ] AC-6: Cache `filtrosDistintos` inclui `prioridades[]`, `setores[]` e `associacoes[]`
- [ ] AC-7: Busca "projetos de alta prioridade em Florianópolis" retorna projetos filtrados corretamente

## Implementação

### Nó 1: `ConsultaDistintos` (SQL)
Adicionar ao final da query existente:

```sql
UNION ALL SELECT 'PRIORIDADE' AS TIPO_CAMPO, PRIORIDADE AS VALOR
FROM (SELECT DISTINCT PRIORIDADE FROM VW_PROJETO_BUSCA_AVANCADA_IA
      WHERE PRIORIDADE IS NOT NULL ORDER BY PRIORIDADE)
UNION ALL SELECT 'SETOR' AS TIPO_CAMPO, SETOR AS VALOR
FROM (SELECT DISTINCT SETOR FROM VW_PROJETO_BUSCA_AVANCADA_IA
      WHERE SETOR IS NOT NULL ORDER BY SETOR) WHERE ROWNUM <= 100
UNION ALL SELECT 'ASSOCIACAO' AS TIPO_CAMPO, ASSOCIACAO AS VALOR
FROM (SELECT DISTINCT ASSOCIACAO FROM VW_PROJETO_BUSCA_AVANCADA_IA
      WHERE ASSOCIACAO IS NOT NULL ORDER BY ASSOCIACAO) WHERE ROWNUM <= 100
```
