# Story 1.6 — Remover Credenciais Hardcoded do JSON via Variáveis de Ambiente

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.6
**Prioridade:** Alta
**Estimativa:** S (2–3h)

---

## Descrição

O `projeta-sc.json` contém duas credenciais hardcoded que impedem o arquivo de ser publicado no GitHub:

| Credencial | Nós afetados | Padrão |
|-----------|-------------|--------|
| Groq API Key (`gsk_...`) | `GroqClassificador`, `GroqRefinamento`, `InterpretaConsulta` | Header `Authorization` |
| Evolution API Key | `RetornoBoasVindas`, `RetornoProjeto`, `RetornaMensagem`, `RetornoReinicio`, `RespondePerguntas` + outros nós de resposta WhatsApp | Header `apikey` |

**Abordagem escolhida: expressões `$env` do n8n**

O n8n suporta `={{ $env.NOME_VARIAVEL }}` em qualquer campo de expressão, incluindo headers de HTTP Request. Isso substitui o valor hardcoded por uma referência a variável de ambiente configurada no servidor — sem custo de plano, sem dependência de features pagas.

```
Antes:  "value": "gsk_xxxxxxxxxxxxxxxxxxxxxxxx"
Depois: "value": "={{ $env.GROQ_API_KEY }}"

Antes:  "value": "7D5DDE6A591F-4D89-9FAC-785A343AD4F8"
Depois: "value": "={{ $env.EVOLUTION_API_KEY }}"
```

O JSON exportado passa a ser limpo — pode ir ao GitHub sem bloqueio.

**Valor:** Elimina exposição de credenciais no repositório. Desbloqueia o push do `projeta-sc.json`. Permite rotação de chaves sem tocar no fluxo n8n.

---

## Workflow de Desenvolvimento

```
1. VERIFICAÇÃO PRÉVIA:
   a. No n8n, criar um nó Code temporário e testar:
      return [{ valor: $env.TEST_VAR || "env não disponível" }]
   b. Se retornar "env não disponível" → seguir Caminho B (abaixo)
   c. Se funcionar → seguir Caminho A

2. CAMINHO A — $env disponível (auto-hospedado EasyPanel):
   a. No painel do servidor (EasyPanel / Docker), adicionar variáveis:
      GROQ_API_KEY=gsk_...
      EVOLUTION_API_KEY=7D5DDE6A591F-...
   b. Reiniciar o container n8n para carregar as vars
   c. Importar docs/flow/projeta-sc.json no n8n
   d. Em cada nó afetado, trocar o valor hardcoded pela expressão $env
   e. Testar o fluxo completo
   f. Exportar e substituir docs/flow/projeta-sc.json
   g. Verificar que o JSON não contém gsk_ nem o valor da Evolution key
   h. Commitar e fazer push

3. CAMINHO B — $env não disponível (fallback):
   a. Manter docs/flow/projeta-sc.json no .gitignore
   b. Criar docs/flow/projeta-sc.template.json com placeholders:
      GROQ_API_KEY_PLACEHOLDER e EVOLUTION_API_KEY_PLACEHOLDER
   c. Documentar no README como restaurar as chaves para uso local
   d. Commitar apenas o template
```

## Acceptance Criteria

### AC-1: Verificação de suporte a `$env`

- [ ] Testar `={{ $env.GROQ_API_KEY }}` em um nó do fluxo
- [ ] Documentar no Change Log: `$env` funciona ou não funciona nesta instância

### AC-2 (Caminho A): Groq API Key substituída

- [ ] Nos nós `GroqClassificador`, `GroqRefinamento`, `InterpretaConsulta`:
  - Header `Authorization` usa `={{ $env.GROQ_API_KEY }}`
- [ ] Variável `GROQ_API_KEY` configurada no servidor com o valor atual
- [ ] Os 3 nós respondem normalmente após a troca

### AC-3 (Caminho A): Evolution API Key substituída

- [ ] Em todos os nós de resposta WhatsApp, o header `apikey` usa `={{ $env.EVOLUTION_API_KEY }}`
- [ ] Variável `EVOLUTION_API_KEY` configurada no servidor
- [ ] Mensagens WhatsApp enviadas normalmente após a troca

### AC-4: JSON limpo verificado

- [ ] `projeta-sc.json` exportado não contém `gsk_`
- [ ] `projeta-sc.json` exportado não contém o valor da Evolution API Key
- [ ] O arquivo pode ser pushed ao GitHub sem bloqueio do Secret Scanning

### AC-5: `.env.example` atualizado

- [ ] Adicionar ao `.env.example`:
  ```
  # n8n Flow — Credenciais do Projeta SC
  GROQ_API_KEY=          # Chave Groq (gsk_...)
  EVOLUTION_API_KEY=     # Chave Evolution API para WhatsApp
  ```

### AC-6 (Caminho B — fallback): Template criado

- [ ] `docs/flow/projeta-sc.template.json` criado com placeholders
- [ ] `docs/flow/projeta-sc.json` adicionado ao `.gitignore`
- [ ] README ou CLAUDE.md documenta como restaurar chaves para uso local

## Cenários de Teste

| Cenário | Ação | Resultado esperado |
|---------|------|--------------------|
| Classificação de intent | Enviar "quero buscar um projeto" | `GroqClassificador` responde normalmente |
| Refinamento | Busca com muitos resultados | `GroqRefinamento` gera mensagem natural |
| Resposta WhatsApp | Qualquer interação | Mensagem entregue via Evolution API |
| JSON limpo | `grep gsk_ projeta-sc.json` | Saída vazia |
| Push GitHub | `git push` | Sem bloqueio de Secret Scanning |

## Escopo

**IN:**
- Substituição de credenciais hardcoded nos nós HTTP Request
- Configuração de variáveis de ambiente no servidor n8n
- Atualização do `.env.example`
- Verificação de suporte a `$env` na instância atual

**OUT:**
- Rotação das chaves (troca pelos valores atuais — recomendado mas separado)
- Migração para n8n Credentials nativas (abordagem anterior descartada)
- Alteração da lógica de negócio dos nós

---

## Dependências

- Acesso ao painel do servidor onde o n8n está hospedado (EasyPanel ou equivalente)
- Valores atuais das credenciais (`gsk_...` e Evolution key) disponíveis

---

## Riscos

- **`$env` não disponível na instância:** Se a instância n8n não expõe variáveis de ambiente nas expressões, o Caminho B (template + .gitignore) é o fallback. Documentar o resultado do AC-1 antes de prosseguir.
- **Reinicialização do container:** Adicionar variáveis de ambiente ao container n8n requer reinicialização, o que interrompe o fluxo brevemente. Planejar em horário de baixo uso.
- **Nós não testados:** Se algum nó de resposta WhatsApp for esquecido, ele falhará em runtime com 401. Testar fluxo completo antes de commitar.
