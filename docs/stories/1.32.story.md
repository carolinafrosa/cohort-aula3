# Story 1.32 — Clones Especializados por Setor de Infraestrutura

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.32
**Prioridade:** Baixa
**Estimativa:** M (4–6h de edição no n8n)

---

## Descrição

O chatbot usa um único prompt de sistema genérico para responder perguntas sobre projetos de qualquer categoria (Rodovias, Habitação, Saneamento, Saúde, etc.). Um técnico de rodovias e um técnico de habitação usam vocabulários completamente diferentes — o bot responde de forma genérica para ambos.

Esta story implementa **clones de persona especializados**: o bot detecta a categoria do projeto consultado e ativa um prompt de sistema específico para aquele setor, com vocabulário técnico, exemplos e tom adequados.

```
Usuário consulta projeto → categoria detectada (ex: "RODOVIAS")
    → Clone Rodovias ativo: "Engenheiro de Infraestrutura Viária"
    → Respostas com vocabulário de pavimentação, drenagem, OAE

Usuário consulta projeto de habitação
    → Clone Habitação ativo: "Especialista em Habitação Social"
    → Respostas com vocabulário de UH, PMCMV, regularização fundiária
```

**Valor:** Usuários técnicos (engenheiros, fiscais do governo) percebem imediatamente que o assistente "entende" do assunto deles. Aumenta confiança nas respostas e reduz mal-entendidos terminológicos.

## Workflow de Desenvolvimento

```
1. Mapear as categorias de projeto mais frequentes no banco Oracle (executar
   SELECT CATEGORIA, COUNT(*) FROM PROJETOS GROUP BY CATEGORIA ORDER BY 2 DESC)
2. Para as top 5 categorias, escrever um mini-prompt de persona especializada (50-80 tokens cada)
3. Importar docs/flow/projeta-sc.json no n8n
4. Após FormataProjeto (quando categoria está disponível), criar nó "SelecionaClone":
   - Input: categoria do projeto
   - Output: prompt de sistema do clone correspondente (ou prompt genérico se categoria desconhecida)
5. Passar o prompt do clone para o nó Reformatter (Story 1.26) como variável
6. Testar com projetos de diferentes categorias
7. Exportar e substituir docs/flow/projeta-sc.json
8. Commitar
```

## Acceptance Criteria

### AC-1: Categorias mapeadas
- [ ] Top 5 categorias de projeto identificadas no banco Oracle
- [ ] Cada categoria tem um mini-prompt de persona (50-80 tokens) com: nome do especialista, vocabulário técnico chave, tom específico

### AC-2: Seleção automática de clone por categoria
- [ ] O nó `SelecionaClone` detecta a categoria do projeto e seleciona o prompt correspondente
- [ ] Categorias não mapeadas usam o prompt genérico (sem degradação)

### AC-3: Clone integrado ao Reformatter
- [ ] O prompt do clone é passado como variável para o nó reformatter LLM (Story 1.26)
- [ ] Se a Story 1.26 não estiver implementada, o clone opera como nó independente após `FormataProjeto`

### AC-4: Vocabulário técnico presente nas respostas
- [ ] Para projetos de Rodovias, respostas usam termos como "pavimentação", "OAE", "faixa de domínio" quando aplicável
- [ ] Para projetos de Habitação, respostas usam "unidade habitacional", "regularização", "beneficiários" quando aplicável

## Escopo

**IN:**
- Mini-prompts de persona para top 5 categorias de projeto
- Nó `SelecionaClone` que seleciona prompt por categoria
- Integração com Reformatter LLM (Story 1.26) se disponível

**OUT:**
- Clones com memória ou histórico de conversas
- Interface para edição dos prompts de clone
- Mais de 5 categorias na primeira implementação

---

## Dependências

- Story 1.26 (Clone Reformatter LLM) — dependência recomendada mas não bloqueante; os clones podem operar como reformatters independentes
- **Pré-condição bloqueante:** Executar `SELECT CATEGORIA, COUNT(*) FROM PROJETOS GROUP BY CATEGORIA ORDER BY 2 DESC` no Oracle antes de iniciar. O resultado deve ser documentado no Change Log desta story. Sem esse dado, os mini-prompts de persona não podem ser escritos com vocabulário correto.

---

## Riscos

- **Categorias não uniformes no banco:** O campo de categoria pode ter valores inconsistentes ("RODOVIAS", "Rodovias", "INFRA VIÁRIA") → normalizar no nó `SelecionaClone`
- **Prompt muito longo:** Acumular mini-prompts pode estourar o context window do modelo leve → manter cada mini-prompt em 60-80 tokens
