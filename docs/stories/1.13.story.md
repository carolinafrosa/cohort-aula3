# Story 1.13 — Ajustar Temperature dos LLMs para Tom Conversacional

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.13
**Prioridade:** Média
**Estimativa:** XS (30min de edição no n8n)

---

## Descrição

Os nós que geram respostas em linguagem natural estão configurados com `temperature` muito baixa:

| Nó | Temperature atual | Função |
|----|------------------|--------|
| `PreparaPromptRefinamento` | **0** | Gera mensagem de refinamento de busca |
| `PreparaPromptPergunta` | **0.3** | Responde perguntas livres sobre projetos |

`temperature: 0` instrui o modelo a ser completamente determinístico — produz sempre a mesma resposta para o mesmo input. Para um classificador ou extrator isso é ideal. Para uma conversa humana, resulta em respostas mecânicas, formulaicas e previsíveis — exatamente o oposto do ChatGPT.

Os nós de classificação (`GroqClassificador`) e extração (`InterpretaConsulta`) estão corretos em `temperature: 0` e não devem ser alterados.

**Valor:** Ajuste mínimo de configuração com impacto direto no tom conversacional das respostas geradas pelo LLM.

---

## Workflow de Desenvolvimento

```
1. Importar docs/flow/projeta-sc.json no n8n (Settings → Import)
2. Editar o nó PreparaPromptRefinamento:
   - No JSON do request_body, alterar "temperature": 0 para "temperature": 0.3
3. Editar o nó PreparaPromptPergunta:
   - No JSON do request_body, alterar "temperature": 0.3 para "temperature": 0.6
4. Testar fazendo perguntas abertas e buscas que ativam o refinamento
5. Exportar (Download JSON) e substituir docs/flow/projeta-sc.json
6. Commitar
```

## Acceptance Criteria

### AC-1: PreparaPromptRefinamento — temperature ajustada
- [ ] Campo `temperature` no JSON do `request_body` alterado de `0` para `0.3`
- [ ] Os demais campos do request_body permanecem inalterados (`model`, `max_tokens`, `messages`)

### AC-2: PreparaPromptPergunta — temperature ajustada
- [ ] Campo `temperature` no JSON do `request_body` alterado de `0.3` para `0.6`
- [ ] Os demais campos do request_body permanecem inalterados

### AC-3: Nós de classificação/extração inalterados
- [ ] `GroqClassificador` permanece com `temperature: 0`
- [ ] `InterpretaConsulta` permanece com `temperature: 0`
- [ ] `GroqRefinamento` (o nó HTTP que chama o Groq, não o Code node) não é afetado — ele não tem temperature, apenas repassa o body

### AC-4: Qualidade das respostas após ajuste
- [ ] Respostas do refinamento soam mais naturais e variadas para inputs similares
- [ ] Respostas do Q&A livre têm tom mais conversacional
- [ ] Nenhuma resposta do classificador foi afetada (classificação correta mantida)

---

## Cenários de Teste

| Cenário | Ação | Resultado esperado |
|---------|------|--------------------|
| Refinamento | Buscar "escola", aguardar mensagem de refinamento | Tom mais natural, não mecânico |
| Q&A simples | Selecionar projeto, perguntar "qual o prazo?" | Resposta fluida, conversacional |
| Q&A contextual | Perguntar "isso é muito dinheiro?" sobre um projeto | Resposta com personalidade |
| Classificação | Enviar "ver contratos", "oi", "buscar escola" | Classificação correta (sem regressão) |

## Escopo

**IN:**
- Alteração do valor `temperature` em `PreparaPromptRefinamento` e `PreparaPromptPergunta`

**OUT:**
- Alteração de qualquer outro parâmetro dos nós (model, max_tokens, system prompt)
- Alteração nos nós de classificação (`GroqClassificador`) e extração (`InterpretaConsulta`)

## Dependências

- Nenhuma dependência de outras stories

## Riscos

- **Variabilidade aumentada:** Temperature mais alta pode gerar respostas ligeiramente diferentes para o mesmo input. Isso é intencional e desejável para conversação. Se respostas incoerentes aparecerem nos testes, reduzir para 0.5 (Q&A) e 0.2 (refinamento).
