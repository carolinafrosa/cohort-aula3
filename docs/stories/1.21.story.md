# Story 1.21 — Exibir Filtros Ativos no Refinamento

**Status:** Ready
**Epic:** 1 — Qualidade e UX do Chatbot
**Story ID:** 1.21
**Prioridade:** Média
**Estimativa:** S (2–3h de edição no n8n)

---

## Descrição

Quando o usuário aplica filtros acumulados (município + órgão + tipo + situação), o sistema os armazena corretamente em `campos_acumulados`. Porém, **nenhuma mensagem exibe explicitamente o que está ativo**. O LLM de refinamento (`GroqRefinamento`) recebe os filtros como contexto e pode ou não mencioná-los na resposta — comportamento não garantido.

O resultado: o usuário não sabe o que filtrou. Ao receber uma lista menor de projetos, não entende por quê. Não sabe que pode "remover municipio" para ampliar a busca, porque nunca foi informado disso.

**Solução:** Injetar um bloco de "filtros ativos" fixo no topo da mensagem de refinamento, gerado diretamente no nó `FormataRefinamento` (sem depender do LLM), seguido pela resposta natural do Groq.

**Valor:** O cidadão entende o estado atual da busca, pode refinar com consciência, e descobre os comandos de remoção de filtro — reduzindo abandono por confusão.

---

## Workflow de Desenvolvimento

```
1. Importar docs/flow/projeta-sc.json no n8n (Settings → Import)
2. Editar o nó FormataRefinamento (Code node):
   - Ler campos_acumulados do contexto da sessão
   - Gerar bloco de "filtros ativos" (se houver filtros)
   - Prepend ao texto da resposta do LLM
3. Testar com busca ampla → aplicar município → ver cabeçalho
4. Testar remoção: "remover municipio" → cabeçalho atualiza
5. Exportar (Download JSON) e substituir docs/flow/projeta-sc.json
6. Commitar
```

## Acceptance Criteria

### AC-1: Bloco de filtros ativos exibido quando há filtros

- [ ] Quando `campos_acumulados` contém ao menos um filtro com valor não-vazio e não-`QUALQUER`, o início da mensagem de refinamento mostra:

  ```
  🔍 *Busca atual:*
  📍 Município: Florianópolis
  🏛 Órgão: DEINFRA
  
  _(Para remover um filtro, digite ex: "remover município")_
  
  {resposta do LLM}
  ```

- [ ] O bloco é gerado no nó `FormataRefinamento`, não pelo LLM
- [ ] O texto da resposta do LLM é mantido integralmente após o bloco

### AC-2: Bloco omitido quando não há filtros ativos

- [ ] Quando `campos_acumulados` está vazio ou tem apenas `QUALQUER` nos valores, nenhum bloco de filtros é exibido
- [ ] A mensagem do LLM é enviada sem prefixo

### AC-3: Mapeamento de campos para labels legíveis

- [ ] Os campos são exibidos com labels em português e emojis:

  | Campo | Label | Emoji |
  |-------|-------|-------|
  | `municipio` | Município | 📍 |
  | `orgao` | Órgão | 🏛 |
  | `tipo` | Tipo | 🏗 |
  | `situacao` | Situação | 📊 |
  | `nome` | Nome | 🔤 |
  | `codigo` | Código | 📄 |
  | `ano` | Ano | 📅 |

- [ ] Campos com valor `QUALQUER` (filtro pulado) não são exibidos no bloco

### AC-4: Hint de "remover filtro" condicional

- [ ] O hint `_(Para remover um filtro, digite ex: "remover município")_` só aparece se houver 2 ou mais filtros ativos — não aparece com filtro único (seria excessivo)

---

## Cenários de Teste

| Cenário | Ação | Resultado esperado |
|---------|------|--------------------|
| Busca sem filtros | Digitar "escola" | Sem bloco de filtros, só resposta do LLM |
| 1 filtro ativo | Aplicar município | Bloco mostra "📍 Município: X", sem hint de remover |
| 2+ filtros ativos | Aplicar município + órgão | Bloco mostra ambos + hint de remover |
| Remover filtro | "remover município" | Próxima resposta não tem mais o município no bloco |
| Filtro pulado (QUALQUER) | Pular campo de órgão | Campo não aparece no bloco |

## Escopo

**IN:**
- Alteração no nó `FormataRefinamento` (Code node) para ler contexto e gerar bloco
- O nó já tem acesso ao `remetente` e pode ler `staticData.contextos[remetente].campos_acumulados`

**OUT:**
- Alteração no prompt do `PreparaPromptRefinamento` (o LLM continua com o mesmo contexto)
- Alteração na lógica de acúmulo de filtros em `ProcessaMensagem`
- Exibição de filtros na lista de projetos (apenas no refinamento)

## Riscos

- **`staticData` acessível em `FormataRefinamento`:** O nó `FormataRefinamento` atualmente usa `$('ProcessaResultados').first().json.remetente` para ler o remetente. Precisa também acessar `$getWorkflowStaticData('global')` para ler `campos_acumulados`. Verificar que o n8n permite múltiplos `$()` e `$getWorkflowStaticData` no mesmo nó Code.
- **Campos nulos ou undefined:** Se `campos_acumulados` for `null` ou não existir, o código deve tratar graciosamente sem quebrar o fluxo.
